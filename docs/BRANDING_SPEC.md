## 3. สีทั้งระบบ = สี CI ของ Kasetphand เท่านั้น

**กฎเหล็ก:** ทุก hex ในแอปต้องมาจากตาราง 3.1 ห้ามคิดสีเอง ห้ามใช้ palette ของ Tailwind/shadcn (`red-500`, `slate-*` ฯลฯ) ถ้าต้องการสีอ่อนหรือเข้มกว่านี้ให้เลือกขั้นจากบันไดสีในตาราง ถ้าไม่มีขั้นที่ใช้ได้ ให้หยุดถาม

ข้อยกเว้นเดียว: `#FFFFFF` สำหรับพื้นการ์ด (CI เองวางโลโก้บนหน้าขาว)

**กฎ opacity** *(ตัดสิน 2026-09-11)* — เดิมห้ามใช้ opacity ทุกกรณี ปรับเป็นแยกตามหน้าที่ของสี

| | กรณี |
|---|---|
| **ห้าม** | พื้นและขอบของสถานะ (ok/warning/critical/offline), สีที่ใช้แยกชุดข้อมูลในกราฟ, สีข้อความ |
| **อนุญาต** | hover, pressed, disabled, focus ring, backdrop ของ dialog/drawer, skeleton, พื้นใต้เส้นกราฟ (area fill) |

เหตุผล: สามกรณีที่ห้ามคือจุดที่สีต้องผ่านเกณฑ์ contrast หรือต้องแยกออกจากกันได้จริง — opacity ทำให้ค่าที่คำนวณไว้ในข้อ 3.2–3.4 ใช้ไม่ได้
ส่วนที่อนุญาตเป็น state ชั่วคราวหรือพื้นหลังที่ไม่ได้แบกความหมาย

**กฎการใช้แดง:** แดงใน chrome (โลโก้, nav active, ปุ่ม primary) = แบรนด์ ส่วนแดงในพื้นที่ข้อมูล (การ์ด, กราฟ, ตาราง) = วิกฤตเท่านั้น ห้ามใช้แดงตกแต่งในพื้นที่ข้อมูล

**การแยกความหมายของ `--primary`** *(ตัดสิน 2026-09-11)*

เดิม `--primary` เป็นสีน้ำเงินและถูกใช้ปนกันหลายความหมาย พอเปลี่ยนเป็น Cinnabar ต้องแยกออกเป็น 4 ทาง

| ใช้ที่ | token ใหม่ |
|---|---|
| ปุ่ม primary, nav active, tabs, ลิงก์หลัก | `brand` (Cinnabar) |
| focus ring | `--ring` = Blue-500 |
| Switch / Checkbox / Radio / Slider สถานะติ๊กแล้ว | `control-checked` = Argent-900 (dark: Lynx White) |
| Progress ที่แสดงปริมาณน้ำ | `data-water` |
| Progress ของงาน (OTA, export) | Argent-900 |

รายการทุกจุดในโค้ดพร้อมจำนวน อยู่ใน `docs/DESIGN_PLAN.md` ข้อ 11

**กฎสีของกราฟ** *(ตัดสินรอบสอง 2026-09-11 — ชุด 4 สีเดิมไม่ผ่าน validator ทั้งสองโหมด ดู `docs/DESIGN_PLAN.md` ข้อ 9)*

|---|---|---|
| ชุดหลักที่ 1 | Blue-500 `#026BB5` | Blue-300 `#4E80BF` |
| ชุดหลักที่ 2 | Green-500 `#009148` | Green-300 `#4CA062` |
| ชุดอ้างอิง | Argent-100 `#CBC7C8` | Argent-800 `#6D6C71` |

**เลือกสีตามรูปแบบของกราฟ ไม่ใช่ตามลำดับชุดข้อมูล**

| รูปแบบกราฟ | สีที่ใช้ |
|---|---|
| ชุดเดียว (รวมกราฟ 8 โซน) | Blue + ป้ายชื่อกำกับ |
| 2 ตัวแปรคนละชนิด | Blue + Green |
| ค่าจริง vs ค่าพยากรณ์ | **สีเดียวกัน** ต่างที่เส้นทึบ/เส้นประ + ช่วงความเชื่อมั่นใช้ `data-water-soft` |
| เทียบช่วงก่อนหน้า / baseline | ปัจจุบัน = Blue, อ้างอิง = Argent + ต้องมี legend |
| กราฟที่มีเส้น threshold สถานะ | Blue ชุดเดียว **ห้ามใช้ Green** (จะชนกับสีสถานะปกติ) |

- **ห้ามใช้แดงเป็นสีชุดข้อมูล** — แดงในพื้นที่ข้อมูลหมายถึงวิกฤตเท่านั้น
- **ห้ามใช้เทาเป็นชุดข้อมูลหลัก** — เทาใช้ได้เฉพาะ**ชุดอ้างอิง**ที่ตั้งใจให้ถอยหลังฉาก (ต้องมี legend เสมอ)
- ต้องรัน validator ของ skill `dataviz` ใหม่ทั้ง light และ dark ทุกครั้งที่แตะชุดสีนี้ — **คู่ไหนไม่ผ่านให้หยุดรายงาน ห้ามเติมสีนอก CI เพื่อให้ผ่าน**
- ระหว่าง Phase 7.4–7.8 **ถ้าเจอกราฟที่ต้องการเกิน 3 ชุดข้อมูลจริง ให้หยุดรายงาน** อย่าเพิ่มสีเอง

### 3.4 Status pill (ทุกคู่ผ่าน ≥ 4.5:1 ใช้ได้ทั้งบนพื้นขาวและพื้นเข้ม)

น้ำหนักทางสายตาเพิ่มตามความรุนแรง: ปกติ/offline ไม่มีพื้น, เตือนมีพื้นอ่อน, วิกฤตมีพื้นเข้มเต็ม

| สถานะ | พื้น pill | ข้อความ | Contrast | จุด/ไอคอน |
|---|---|---|---|---|
| ปกติ | ไม่มี | Green-800 `#526E57` | 5.6 | จุด Green-500 `#009148` |
| เตือน | Marigold-100 `#FDD8A3` | Marigold-900 `#625B4B` | 5.0 | ไอคอน Marigold-900 |
| วิกฤต | Cinnabar-700 `#BC5242` | `#FFFFFF` | 4.8 | ไอคอนขาว |
| Offline | ไม่มี | Argent-800 `#6D6C71` | 5.2 | จุด Argent-500 `#888888` |

ทุก pill ต้องมี **ไอคอน + ข้อความ** เสมอ ห้ามสื่อสถานะด้วยสีอย่างเดียว

### 3.5 ปุ่ม primary

Cinnabar-500 + ตัวอักษรขาว = 4.42:1 (ขาดเกณฑ์ AA 4.5 อยู่ 0.08)

**ทางที่เลือก: (ก) ใช้ Cinnabar-500 + ตัวอักษรขาว** *(ตัดสิน 2026-09-11 — เปลี่ยนได้)*

- ตัวอักษรบนพื้น Cinnabar-500 ต้อง **≥ 16px และ weight 600** เสมอ
- **ตัวอักษร < 16px ห้ามวางบนพื้น Cinnabar-500** ทุกกรณี — ถ้าจำเป็นต้องมีปุ่มเล็ก ให้ใช้พื้น Cinnabar-700 `#BC5242` (4.8:1) แทน
- **nav active pill ใช้กติกาเดียวกัน** (พื้น Cinnabar-500 ตัวอักษรขาว ≥ 16px / 600)
- นี่คือ**ข้อยกเว้นที่รับรู้แล้ว**ว่าต่ำกว่าเกณฑ์ AA สำหรับข้อความเล็ก 0.08 — บันทึกเหตุผลและขอบเขตไว้ใน `docs/DESIGN_PLAN.md`
- 16px/600 ยังไม่นับเป็น "ข้อความใหญ่" ตาม WCAG (ต้อง 18.66px bold) จึงถือเป็นการยอมรับความเสี่ยงเชิงแบรนด์ ไม่ใช่การผ่านเกณฑ์

### 3.6 Dark mode

`CLAUDE.md` บังคับให้รองรับ dark mode แต่ CI ไม่มีชุดสีสำหรับพื้นเข้ม ขั้นเข้มสุดในบันไดคือ Argent-900 `#515558` ซึ่งยังไม่มืดพอสำหรับจอห้องควบคุม และ Cinnabar-500 บนพื้นนี้ได้ contrast แค่ 1.7:1

**ทางที่เลือก: (ข) ขยายเฉพาะเทา** *(ตัดสิน 2026-09-11 — เปลี่ยนได้)*

- เพิ่ม Argent-950 และ Argent-1000 ต่อจากบันได Argent โดยคง hue เดิม ใช้เป็น**พื้นของ dark mode เท่านั้น** (ดูตารางท้ายข้อ 3.1)
- ค่า hex ที่เสนอและวิธีคำนวณอยู่ใน `docs/DESIGN_PLAN.md` — ต้องคง H และ S ของบันได Argent ไว้ เปลี่ยนเฉพาะ L
- สีที่มีโทนทุกสีใน dark mode ยังต้องเป็นขั้นจากตาราง 3.1 ห้ามคิดสีใหม่
- ต้องแจ้งเจ้าของแบรนด์ว่ามี 2 ค่าที่อยู่นอก CI (open question ค้างไว้จนกว่าจะได้คำตอบ)

- (ก) **CI เคร่งครัด:** dark mode ใช้ Argent-900 เป็นพื้นหน้า, Argent-800 เป็นการ์ด, ข้อความ Lynx White (4.9–7.0:1), สถานะใช้ pill แบบมีพื้นจาก 3.4 เท่านั้น, กราฟใช้ขั้น 100 — ข้อเสีย: พื้นเป็นเทากลางไม่ใช่มืดจริง และกราฟ contrast ต่ำ
- (ข) **ขยายเฉพาะเทา:** เพิ่ม Argent-950 และ Argent-1000 (เทาเข้มกว่า ต่อจากบันไดเดิมโดยไม่เปลี่ยน hue) ใช้เป็นพื้นของ dark mode เท่านั้น ส่วนสีมีโทนทุกสีคงเป็นขั้นจาก CI — ข้อเสีย: มี 2 ค่าที่ไม่อยู่ใน CI ต้องแจ้งเจ้าของแบรนด์

### 3.7 สีในโค้ดที่ไม่ใช่ CSS class

- **shadcn:** map ค่าจากข้อ 3.3 เข้าตัวแปรเดิมใน `app/globals.css` (`--primary`, `--destructive`, `--border`, `--ring` ฯลฯ) โดย**คงรูปแบบค่าที่ไฟล์ใช้อยู่** (HSL หรือ oklch) และใส่คอมเมนต์ hex ต้นฉบับข้างทุกตัว — component ของ shadcn จะได้สี CI โดยไม่ต้องแก้ทีละตัว
- **Recharts / SVG เขียนมือ** (tank gauge, ผังการไหล): อ่านสีจาก `lib/config/theme.ts` จุดเดียว ห้ามใส่ hex ใน props ของกราฟ
- **`lib/config/anomaly-types.ts`:** สีของแต่ละ type ต้องชี้ไป semantic token ไม่ใช่ hex, และ type ที่ไม่รู้จักใช้สี `text-secondary` + ไอคอน default
- Test whitelist ต้องแปลงค่า HSL/oklch กลับเป็น hex ก่อนเทียบกับตาราง 3.1 (ยอมคลาดจากการปัดเศษ ±1 ต่อ channel)
- **`app/layout.tsx` — `themeColor`** *(ตัดสิน 2026-09-11)*: ทั้งสองค่า import จาก `lib/config/theme.ts` ห้ามเขียน hex ซ้ำในไฟล์นี้ — light = Lynx White `#F7F7F7`, dark = พื้นหน้าของ dark mode (Argent-1000 ตามข้อ 3.6)

## 4. Typography

- **ไทย:** IBM Plex Sans Thai ที่ bundle อยู่แล้วใน `app/fonts/` — คงไว้ (CI ฉบับนี้ไม่ระบุฟอนต์ไทย)
- **อังกฤษ + ตัวเลข:** Montserrat ตาม CI — วางไฟล์ `.woff2` (OFL) น้ำหนัก 400/500/600/800 ใน `app/fonts/` แล้วโหลดด้วย `next/font/local` ห้ามใช้ `next/font/google` หรือแพ็กเกจ `@fontsource`
- **วิธีได้ไฟล์** *(ตัดสิน 2026-09-11)*: ดาวน์โหลด `Montserrat[wght].ttf` จาก `github.com/google/fonts` (`ofl/montserrat`) → subset เฉพาะ Latin แล้วแปลงเป็น woff2 ด้วย `fonttools` (ติดตั้งด้วย pip บนเครื่องพัฒนา **ห้ามเพิ่มใน `package.json`**)
  - ต้องใส่ `--layout-features+=tnum,lnum` ตอน subset ไม่งั้น tabular-nums จะใช้ไม่ได้
  - วาง `OFL.txt` ไว้คู่กับไฟล์ฟอนต์ใน `app/fonts/`
  - การดาวน์โหลดเกิดบนเครื่องพัฒนาเท่านั้น ตัว build ยัง self-host 100%
- Font stack: `Montserrat, "IBM Plex Sans Thai", sans-serif` — อักษรละตินและตัวเลขเป็น Montserrat ส่วนไทยตกไปที่ IBM Plex Sans Thai
- Montserrat ExtraBold 800 ใช้เฉพาะชื่อหน้าและตัวเลข KPI ใหญ่, label 500–600, body 400
- IBM Plex Sans Thai หนักสุดที่ 700 → หัวข้อภาษาไทยตั้ง `font-weight: 700` อย่าตั้ง 800 (เบราว์เซอร์จะทำตัวหนาปลอม)
- ตัวเลขที่อัปเดต realtime ใช้ `font-variant-numeric: tabular-nums` (ใส่ใน util/format หรือ class กลาง ไม่กระจายทีละ component)
- ตัวเลข KPI สำหรับจอแขวนผนัง: ≥ 48px ที่ 1920px, ≥ 32px ที่ 375px, สี `text-primary` หรือ `data-water`

## 5. โลโก้

### 5.1 การได้ไฟล์

**แหล่งเดียวคือหน้า PDF ที่ 11** *(ตัดสิน 2026-09-11)* — หน้า **"Logo Primary / Primary Color Usage"** (มุมขวาบนเขียน 09)
หน้าอื่นในไฟล์มีโลโก้ฝังอยู่เหมือนกัน แต่เป็น**เวอร์ชันหน้าปกที่สัดส่วนผิด** (1.5056 แทนที่จะเป็น 1.40) ห้ามใช้

1. `pdfimages -png -f 11 -l 11 "<pdf>" <out>` → ได้ภาพสไลด์ 2433 × 1369
2. crop เฉพาะกล่องแดง — ต้องได้สัดส่วน **1.40 ± 0.01** (ราว 990 × 708 px)
3. ทำมุมโค้งให้โปร่งใสโดย**วัดรัศมีมุมจากภาพจริง** ไม่ใช่กะเอา แล้วตรวจบนพื้นเข้มว่า**ไม่มีขอบขาว**เหลืออยู่
4. บันทึกเป็น `public/brand/kasetphand-logo.png` และ `@2x`
5. **ห้าม** วาด/trace เป็น SVG เอง, ห้ามตัดเอาเฉพาะตัว K, ห้ามพิมพ์คำว่า KASETPHAND ด้วยฟอนต์

**เกณฑ์ตัดสินว่าไฟล์ที่ได้ใช้ได้ไหม** *(ตัดสิน 2026-09-11)*

- กว้าง **≥ 2 เท่า**ของขนาดที่แสดงใหญ่ที่สุดในแอป
- ขอบตัว K **ไม่มี JPEG artifact** เมื่อซูม 400%
- **ไม่ผ่านเกณฑ์ → ใช้ชั่วคราวได้** แต่ต้องบันทึกเป็น open question ว่าต้องขอไฟล์ต้นฉบับ (ai/svg/png ความละเอียดสูง) จากองค์กร

### 5.2 Component `components/layout/brand-logo.tsx`

- จุดเดียวที่ render โลโก้ในทั้งแอป
- **ใช้สัดส่วนจริงของไฟล์** *(ตัดสิน 2026-09-11)* — ไฟล์ที่ crop มาได้สัดส่วน 14 : 10 อยู่แล้ว จึงวางเต็มกล่องได้ตรง ๆ
  **ห้ามใช้กล่อง `aspect-ratio: 14/10` + `object-fit: contain`** เพราะจะเกิดแถบว่างถ้าไฟล์คลาดไปเล็กน้อย และทำให้ clear space จริงไม่ตรงกับที่คำนวณ
- Clear space ≥ **ความสูงโลโก้ ÷ 10** (CI: กล่องสูง 10x, D กว้าง x, ระยะขอบ 1D)
- สูงขั้นต่ำ 32px (CI ไม่กำหนด — ค่าที่ตัวอักษร KASETPHAND ยังอ่านออก)
- ห้าม shadow, border, opacity < 1, filter, rotate, animation, hover effect, วางบนพื้นแดงหรือพื้นลาย, วางทับข้อความ
- Dark mode ใช้โลโก้เดิม
