# ระบบมอนิเตอร์และควบคุมการใช้น้ำในโรงงาน

แดชบอร์ดสำหรับดูระดับน้ำ ปั๊ม มิเตอร์รายโซน และการใช้น้ำแบบเรียลไทม์
เป็นงาน **AIoT capstone** — ส่วนนี้คือ **frontend อย่างเดียว** ข้อมูลทั้งหมดยังเป็น mock

> **ระบบนี้ต้องรันบน VM ในโรงงานที่ไม่มีอินเทอร์เน็ต**
> ฟอนต์ ไอคอน รูปภาพ และไลบรารีทุกตัวจึงถูก bundle มากับ build ทั้งหมด
> ห้ามเพิ่มอะไรที่ต้องเรียก CDN, Google Fonts, map tile หรือ API ภายนอกตอนรัน

---

## เริ่มใช้งาน

```bash
npm install
npm run dev          # เปิด http://localhost:3000
```

เข้าสู่ระบบด้วย **`admin` / `admin1234`**

> หน้า login เป็น UI สาธิตเท่านั้น **ไม่ใช่ระบบยืนยันตัวตนจริง**
> ของจริงต้องกั้นที่เซิร์ฟเวอร์ด้วย middleware ที่ตรวจ cookie ก่อนส่ง HTML

## คำสั่งที่ใช้บ่อย

| คำสั่ง | ทำอะไร |
|---|---|
| `npm run dev` | รันโหมดพัฒนา |
| `npm run build` | build สำหรับขึ้นเครื่องจริง |
| `npm run lint` | ตรวจ ESLint |
| `npx tsc --noEmit` | ตรวจชนิดข้อมูล |
| `npm run check:colors` | ตรวจว่าสีทุกจุดมาจากบันไดสี CI (8 ข้อ) |
| `npm run check:buckets` | ตรวจการตัดช่วงเวลาตามเขตเวลาไทย (8 ข้อ) |
| `npm run check:series` | ตรวจว่าผลรวมรายชั่วโมง = รายวัน = รายเดือน (10 ข้อ) |

**ก่อน push ทุกครั้ง** ต้องผ่านครบ: `tsc` → `lint` → `check:*` → `build`

## หน้าจอในระบบ

| เส้นทาง | หน้า |
|---|---|
| `/` | ภาพรวม — ถัง ปั๊ม มิเตอร์หลัก มิเตอร์รายโซน ค่าน้ำ การแจ้งเตือนล่าสุด สภาพแวดล้อม |
| `/overview` | แผนผังการไหลของน้ำทั้งระบบ |
| `/ai` | ผลจากทีม AI — ความผิดปกติ คำพยากรณ์ การบำรุงรักษาเชิงคาดการณ์ |
| `/control` | สั่งเดิน/หยุดปั๊ม เปิด/ปิดวาล์ว พร้อม audit log |
| `/devices` | สถานะ ESP32 / PLC / gateway และบริการหลังบ้าน |
| `/alerts` | การแจ้งเตือนทั้งหมด ตัวกรอง และการรับทราบ |
| `/reports` | สรุปการใช้น้ำและค่าน้ำ เทียบกับช่วงก่อนหน้า |

**กราฟทุกใบกดเปิดดูย้อนหลังได้** — เลือกช่วงเวลา ความละเอียด เทียบกับช่วงก่อนหน้า
เจาะลึกจากปี → เดือน → วัน → ชั่วโมง และส่งออก CSV

## โครงสร้างโปรเจกต์

```
app/                  หน้าเว็บทั้งหมด (App Router)
components/
  charts/             กราฟกลาง + chart-explorer (หน้าต่างดูข้อมูลย้อนหลัง)
  layout/             header, sidebar, แถบหัวเรื่อง, footer
  tanks/ pumps/ zones/ environment/ control/ devices/ alerts/ ai/
  ui/                 shadcn/ui
lib/
  types.ts            ★ สัญญากับทีมหลังบ้าน — type ทุกตัวอยู่ไฟล์นี้ไฟล์เดียว
  services/           ★ จุดเดียวที่หลังบ้านต้องมาแก้ตอนต่อ API จริง
  mock/               ข้อมูลจำลอง + simulator ที่ขยับเองทุก 2 วินาที
  config/             ทะเบียน metric, สี CI, เขตเวลา
  utils/              จัดรูปแบบตัวเลข/วันที่, ตัดช่วงเวลา
  i18n/               พจนานุกรมไทย/อังกฤษ (ไม่ได้ใช้ไลบรารี i18n)
docs/                 สเปกและเอกสารส่งต่อ
scripts/              สคริปต์ตรวจงานอัตโนมัติ
```

### กฎที่ต้องรู้ก่อนแก้โค้ด

1. **component ห้ามเรียก `lib/mock/` ตรง ๆ** ต้องผ่าน `lib/services/` เสมอ
   เพื่อให้ทีมหลังบ้านสลับเป็น API จริงได้ที่จุดเดียว
2. **type ทุกตัวอยู่ใน `lib/types.ts`** — จะแก้ของเดิมต้องถามก่อน เพราะเป็นสัญญากับทีมอื่น
3. **ห้ามใส่ hex ในโค้ด** สีทุกค่าอยู่ใน `lib/config/theme.ts` แล้วใช้ผ่าน token ของ Tailwind
   (`npm run check:colors` จะจับได้)
4. **ห้ามเพิ่ม dependency** นอกเหนือจาก Next.js / Tailwind / shadcn/ui / Recharts / lucide-react
   โดยไม่ถามก่อน
5. **ของที่มีอยู่ในโค้ดชนะสเปกเสมอ** ถ้าเอกสารกับโค้ดไม่ตรงกัน ให้แก้เอกสาร

รายละเอียดทั้งหมดอยู่ที่ `CLAUDE.md` และ `RUNBOOK.md`

## การทำงานร่วมกัน

```
feature/<ชื่อคุณ>-<สิ่งที่ทำ>  →  dev  →  main
```

- **ห้าม push เข้า `main` หรือ `dev` ตรง ๆ** ให้แตก branch ของตัวเองแล้วเปิด Pull Request
- PR ทุกใบพุ่งเข้า **`dev`** ก่อนเสมอ
- `main` คือของที่พร้อมส่ง — merge จาก `dev` เมื่อทดสอบผ่านแล้วเท่านั้น

ขั้นตอนเต็มอยู่ใน [`docs/GIT_FLOW.md`](docs/GIT_FLOW.md)

ทุก PR จะถูกตรวจอัตโนมัติด้วย `.github/workflows/ci.yml` (ชนิดข้อมูล, lint, สี, ช่วงเวลา, ข้อมูลกราฟ, build)
